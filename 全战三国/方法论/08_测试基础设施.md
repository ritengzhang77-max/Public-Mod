# 08 · 测试基础设施

## 384 里发生了什么

384 的测试分三层，每一层都是被一次真实的失败逼出来的：

1. **离线测试**：一个"假游戏"（`TW3K/tools/fake_game.lua`）+ Lua 5.1 运行器（`run_lua_tests.py`，用 lupa 自带的 Lua 5.1，和游戏内嵌的版本一致）。384 的 `tests/test_era.lua` 现在有 79 条测试，每次构建都跑。
2. **构建关卡**：语法检查、`lint_lua.py`、生成器自己的一致性检查、`check_self_contained.py`。任何一关不过，不打包。
3. **真游戏自测**：脚本自己启动游戏、点鼠标、按键、截图、读日志（`TW3K/tools/gamectl.ps1`），外加一个只做实验的探针包（`rtz_probe`）。

几件逼出这套东西的事：

- 第一次进游戏，**一个人都没生成出来**，日志里只有"已登场 0 人"。离线测试全绿，因为假游戏不知道"名字 id 必须登记在 `names_tables`"这条规矩。最后是在探针包里做了一排"每级只多改一个字段"的模板，逐级对照才找到（findings 第 6 条）。
- **`string.find` 第 4 个参数的写法让整个游戏的 Lua 栈坏掉**（第 7 条）。离线的 Lua 复现不了，只能靠 lint 在构建时拦。
- **别的 Mod 的开局抉择被吞，整局卡死**（第 22 条）。修完之后在假游戏里加了"抉择被吞 → 不能结束回合"的模拟，回归测试在旧写法下确实失败。
- **测试脚本的点击打到了玩家正在用的窗口里**（第 57 条）：玩家在别的窗口打字，游戏没拿到前台，一个 ESC 把那边正在跑的命令取消了。现在 gamectl 只在游戏是前台窗口时才发输入。
- **装包后游戏启动 27 秒就崩**，还没到主菜单：某个数据表的条件指向了不存在的技能键（第 57 条）。靠"去掉一部分数据表重新打包、再启动"二分，两次启动就定位了。

## 一、离线测试：假游戏

- **严格**：假游戏只模拟我们的脚本实际用到的接口，每个都在原版或已装 Mod 的脚本里出现过；调用了没模拟的方法**直接报错**，不悄悄返回 nil——拼错函数名在离线就能抓到。
- **把真游戏里的坑也模拟进去**：存档逐字照搬原版的序列化（不转义字符串、丢数字键）；空接口是"严格空"（调别的方法就报错）；城会被烧成废墟；事件分类被静音时抉择被吞、不能结束回合；原版按钮模板的自动停靠、自动改大小（`fake.assert_layout` 检查窗口里的控件互不重叠、不出窗口）。
- **测试写成"一条规矩一条测试"**，名字就是规矩本身，例如：
  - `the_purge_is_silent_and_the_event_feed_comes_back`
  - `other_mods_start_dilemmas_are_never_swallowed_so_the_turn_can_end`
  - `every_army_leader_has_his_units_in_his_own_retinue`
  - `debut_falls_back_when_the_home_faction_is_gone`
  - `liu_yu_serves_in_the_beifu_army_and_leads_nothing`
  - `using_a_power_spends_points_applies_the_bundle_and_blocks_a_second_use`
- **测试读生成出来的数据**，不写死派系键（壳换过三轮，测试一行没改）。
- **它证明不了什么**：假游戏只能证明"脚本按我们以为的接口行为是对的"。接口在真游戏里到底怎么表现，以探针包和真游戏的实测为准。

## 二、构建关卡

`python TW3K/tools/build.py`（`--install` 顺带拷进游戏的 data 目录）：

1. 按 `mod.json` 的 `prebuild` 顺序跑生成器：立绘 → 旗帜 → 开场动画 → 界面 → 数据表和 Lua 数据 → 开局存档 → 立绘提示词。生成器发现数据不一致就退出（夫妻对不上、金装配给两个人、壳撞了叛军接手派系、没立绘的人没有提示词……）。
2. Lua 语法检查。
3. `lint_lua.py`：合法的 Lua 但已知会弄坏真游戏的写法（现在是 plain `string.find`），出现就不打包。
4. 离线测试。
5. 打包。
6. 发布前另跑 `check_self_contained.py`：包里每张数据表的每个引用，都必须指向原版或包里自己有的键；只在创意工坊 Mod 里有的，报出来（见 [09](09_发布与依赖管理.md)）。

## 三、真游戏自测

**工具**（`gamectl.ps1`，PowerShell，点源后调用）：

| 函数 | 做什么 |
|---|---|
| `Start-Game` / `Stop-Game` | 带 `used_mods.txt;` 参数启动（不带参数一个 Mod 都不加载，第 1 条） |
| `Enter-EightPrinces` 等 | 从主菜单一路点到新开局（约 4～5 分钟） |
| `Click-At` / `Press-Key` / `Scroll-At` / `Move-To` | 输入；只在游戏是前台窗口时才发，拿不到前台就停 |
| `Save-Shot` | 截图（可缩放、可裁切） |
| `Get-RtzLog` | 读游戏目录的 `lua_mod_log.txt` 最后几行 |

**日志是主要证据**：`lua_mod_log.txt` 每次启动游戏都会清空，逐行写入。脚本里的日志写成能直接判断对错的样子（见 [07](07_脚本机制.md)）。**下结论前截图和日志都要看**。

**探针包**：只做实验的小 Mod。游戏目录里放一个开关文件（比如 `rtz_spawn_lab.txt`，写上实验名），它就跑对应的实验并把结果写进日志；用完删掉。384 的借壳实验（休眠派系能不能送城唤醒）、生成实验（为什么一个人都出不来）都是这么做的。

**测试开关**：游戏目录里放 `rtz_era_384_test.txt`，写 `arrivals_turn=2`，所有日后入场的势力改在第 2 回合入场——不用玩到 399 年就能测孙恩起事。测完删掉。

## 四、不碰玩家的东西

每天都要开游戏验证，但游戏装在玩家自己的电脑上，玩家也在玩。规矩：

- **窗口设置**：测试需要固定的分辨率和窗口位置（点击坐标是按它量的）。改之前备份 `preferences.script.txt`，测完、最后一次关游戏之后**恢复备份**（游戏正常退出时会重写这个文件）。
- **Mod 列表**：只开自己一个包的"纯净测试"= 备份 `used_mods.txt`，只写自己的包，测完恢复。
- **存档**：结束回合会在玩家的存档目录里生成自动存档——测完把比玩家最后一次存档新的自动存档挪走；从不手动存档，从不动玩家的存档。
- **包文件**：游戏运行时已加载的包被锁死，不能覆盖（第 32 条），拷包要在游戏关着时做；改过名的旧测试包要从 data 里删掉（一个遗留的 `!!` 电影包会压住新的）。
- **玩家在玩的时候**：只构建、不启动、不关游戏、不往 data 里拷包。读 `lua_mod_log.txt` 是无害的。
- **Steam 要开着**：没开时游戏验证不了 DLC，八王之乱的内容全部上锁、按钮变成「马上购买」，容易误以为是 Mod 的问题。
- 测完清理：游戏目录里放的开关文件、临时包。

## 五、出问题时怎么判断

| 现象 | 多半是 | 怎么查 |
|---|---|---|
| 启动后二三十秒崩，没到主菜单 | 数据表里有悬空的引用 | 去掉一部分数据表文件夹重新打包、启动，二分 |
| 一点「新战役」就崩 | 选派系界面的那几张表 | 同上，只动界面相关的表 |
| 黑屏、日志不再更新、进程"未响应" | 卡死（城防军、Lua 栈被弄坏……） | 看日志最后一行在做什么 |
| 进程直接消失 | 闪退 | 同上；检查空接口、plain `string.find` |
| 不能结束回合 | 有未处理的抉择 / 外交提案 / 改革界面 | 截图找弹窗；八王之乱第一次结束回合会先弹改革界面，AI 回合里别家的外交提案会停住等你点（第 45 条） |
| 脚本"没生效" | 包没装上，或被别的包压过 | 主菜单右下角有没有 "(modded)"；年份对不对；同路径文件谁的优先级高（见 [09](09_发布与依赖管理.md)） |

## 六、所以下次这样做：每天的验证流程

1. `build.py`：生成、检查、离线测试、打包。离线测试不过不进游戏。
2. 确认玩家没在玩；关着游戏时拷包；备份窗口设置和 Mod 列表。
3. 启动（纯净测试就只写自己的包），开新局，选要测的派系，跳过开场动画、清掉开局弹窗。
4. 读第 1 回合的日志，逐行对预期；截图对照界面。
5. 结束回合（处理改革界面、外交提案），等日志里出现第 2 回合的行——**以日志为准**，不以脚本"等到了"为准。
6. 关游戏；挪走自动存档；恢复窗口设置和 Mod 列表；删开关文件。
7. 结论写进版本说明（"已进游戏验证"要写清测的是哪一家、过到第几回合）；新发现的引擎规矩写进 findings，能模拟的补进假游戏。

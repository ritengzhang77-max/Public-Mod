# 01 · 深度研究与人物取材

## 384 里发生了什么

动手之前先比了三个开局年份（`research/start_date_options.md`）：317 年（西晋亡、东晋草创）、352 年（冉魏亡，燕秦晋三足）、384 年（淝水之后）。比的是四件事：

| 标准 | 317 | 352 | 384 |
|---|---|---|---|
| 派系数量、强弱是否均衡 | 名义势力多，但汉赵 + 石勒占了整个中原，坞主一回合就被吞 | 基本是三强垄断，小势力寿命短 | 北方权力真空，没有一家能速推；格局和原版 190 最像 |
| 招牌人物是否"在场" | 刘渊已死、刘聪将死 | 王猛隐居、谢安未出、苻坚 14 岁 | 苻坚、慕容垂、姚苌、谢安、谢玄当打，姚兴、拓跋珪、刘裕、桓玄已出生 |
| 史料够不够 | 胡族二线人物生卒几乎全缺 | 三强尚可 | 《晋书》载记 +《通鉴》卷 105–106 近乎逐月记事，《魏书》列传多有享年 |
| 地图契合度 | — | — | 主要战场全在原版地图里，只有吕光（西域）在图外 |

定下 384 年之后，又定了**快照月份**：六月下旬。这一年局势逐月剧变——换成正月，桓冲、慕容泓还活着、姚苌还没叛秦；换成 385 年，刘库仁、翟斌已死、吕光已东归。月份定死之后，谁活着、谁在哪、谁是君主才有唯一答案。

然后分三层做资料：

1. **人物与派系资料库** `research/era_384.yaml`：由一个研究子代理按史料整理，13 个派系、151 人。我们抽查了 20 个核心人物的生卒年，与通说一致；多数条目没有逐条核对原文，生年不详的 109 人如实标了 `unknown`，没有编。
2. **史料说明** `research/sources_and_caveats.md`：用到了哪些书的哪几卷、联网核对过哪些页面，以及 34 条已知争议（姚苌 / 姚襄生年矛盾、农历十二月跨公历年、苻洪 ≠ 苻宏这类同音易混、"后秦""西燕"都是后世史家的叫法……）。
3. **地盘** `data/province_owners_384.yaml`：游戏地图是东汉的 84 个郡，史料是东汉 105 郡国加"部分 / 争夺中"的注记，两边对不上，只能人工折算。每郡一条，带把握程度和说明，文件末尾列了需要玩家拍板的问题。后来又加了逐城的覆盖（`region_overrides`）：邺城是苻丕死守的孤城、城外的县是慕容垂的；长安归苻坚、城外蓝田是慕容冲的。复核记录在 `research/ownership_384_review.md`。

做到一半才发现的缺口和错误：

- **名人缺口**：拿一张 163 人的名单去对（`research/famous_people_384.md`），资料库里只有 96 人，构建实际生成 67 人。整个刘裕集团、崔宏崔浩、赫连勃勃、沮渠蒙逊、秃发氏、李暠都不在。原因是研究子代理按"384 年当权"收人，漏掉了"384 年还年轻、日后是主角"的一代。
- **补充档案另起一个文件**：原文件 3000 行，不在里面手改；补的人和改动写进 `research/era_384_additions.yaml`（一人一行），生成器把两份合在一起用。
- **年龄估错**：史料没有生年的人，第一版一律按身份估（君主 45、武将 35），结果苻坚 46 岁、儿子苻晖 45 岁；原文件备注里明明写着"应为幼童"的慕容冲之子，被估成了 35 岁的将军。后来写立绘提示词时按父子、履历逐个重推，游戏和立绘用同一个数（见 [03](03_立绘生成流程.md)）。
- **来源不可靠的人**：宁州刺史费统只出现在一张没注出处的维基表里，原书检不到，《通鉴》里的费统是另一个人（385 年的巴西太守）。最后把他去掉，改由史书留下碑文的爨氏当家。
- **史书失名的人**：《爨龙颜碑》只记祖、父的官职，不记名字。游戏需要名字，就用拟名（爨璋、爨琚），并在资料和说明里写明"拟名"。
- **"按史实"比"填满"重要**：晋的府署考证（`research/jin_court_384.md`）查下来，384 年能按史实坐进官位的只有 4 人（谢安、司马道子、谢石、王献之），其余要么外任、要么官职不详。玩家定的规矩是"按史实来"，所以其余官位开局空着，没有硬塞。
- **城池状况**：第一版按"久经丧乱"给不少城挂了残破、饥馑。玩家的意见是：除非史书明确记载某城那年被屠，否则不给，以后每个时代都一样，不然大家都太穷。现在只有 `city_conditions_384.yaml` 里标了 `massacre: true`、并写明史料的城才会残破；384 年没有这样的城。

## 一、资料库的格式

人物一条的字段（`era_384.yaml` 的写法；补充文件是同样的字段，一人一行、缩写）：

| 字段 | 含义 | 注意 |
|---|---|---|
| `id` | 英文 id，全项目唯一 | 同音的人要区分：`fu_hong_heir`（苻宏）不能和苻洪撞 |
| `name` / `courtesy_name` | 姓名、字 | 复姓（慕容、拓跋、乞伏……）生成器要能拆 |
| `birth_year` / `death_year` | 生卒年 | 史无明文就填 `null`，不要估 |
| `birth_year_confidence` | high / medium / low / unknown | low = 按事迹推的 |
| `faction` / `role` | 384 年快照时属于哪家、身份 | role：ruler / heir / general / minister / other |
| `archetype` | 职业（统帅 / 先锋 / 勇士 / 卫士 / 军师） | 决定一辈子哪条属性会涨，见 [04](04_数值设计与五维系统.md) |
| `father` / `mother` / `spouse` / `siblings` | 亲属，只引用本文件里的 id | 史书有载但没收录的写进 notes |
| `alive_at_start` | 快照时是否在世 | false 的人只作世系节点，不生成（王猛、桓冲） |
| `notes` / `sources` | 说明、出处 | "存疑"要写在这里，不当定论 |

补充文件额外有：`est_age`（没有生年时的估计岁数）、`debut` / `fallback`（到年份才登场、本家没了投谁，见 [02](02_人物取舍与分配.md)）、`epithet`（外号）、`wave`（第一波 / 第二波）、`playable: true`（点名放行的女性、僧人）。

派系一条：`id`、名字、君主、都城、东汉郡名写的领地、族属、是否可玩、置信度、说明。

## 二、置信度怎么标

- **人物生年**：high = 正史有享年或明文；medium = 两说并存取其一；low = 按排行、事迹推算；unknown = 无考。
- **地盘**：high = 史书对该郡该时点有明确记载；medium = 大体如此或需要折算地望；low = 拉锯中或纯属游戏性安排（比如"给西燕一块能产粮的地"），要在 note 里直说。
- **"推定"和"拟名"单独写明**：罗友任广州刺史是按履历推出来的（conf: low）；爨璋、爨琚是拟名。说明文字里照样写出来，不要让玩家以为是史实。

## 三、所以下次这样做

1. **比年份**：选 2～3 个候选时点，按上面四条标准各写一段，推荐一个。顺带记下"如果以后做第二、第三个剧本，哪个年份适合"。
2. **定快照月份**：把这一年逐月的大事列出来，挑一个月，写清楚这个月"谁已死、谁未起、谁在哪"。以后所有判断都以这个月为准。
3. **建资料库**：可以交给研究子代理整理初稿，但要求它：生年不详就留空；每人写出处；争议另起一份说明。拿到之后自己抽查核心人物。
4. **对名人清单查缺口**：另列一份"玩家一定会找的人"（包括这一年还年轻、日后是主角的一代），和资料库、和构建实际生成的名单三方核对。缺的补进补充文件，不改原文件。
5. **地盘先郡后城**：先按郡给归属和把握，列出要玩家拍板的问题；换好底板剧本之后再做逐城覆盖。依据写进复核文档。
6. **年龄按亲属链复核**：父亲的岁数减儿子的岁数要说得通；备注里写着"幼童"的人不许按身份估成成年人。
7. **来源弱的人要么降级、要么去掉**：只见于无出处二手表格的人不当君主；失名的人用拟名并注明。
8. **"不编造"的边界写下来**：官位、残破、屠城这类会直接改变玩法的东西，没有史料就不给。

9. **写一份研究委托书，几个时代同一个格式**（2026-09-25 同时开五个时代时补的一步）：交给研究子代理的不是一句“查一下 617 年”，而是一份固定的委托书，写清：
   - 交什么：资料库 yaml（派系、人物、每人一段立绘描述）、84 郡归属 yaml、名人核对表、史料与争议说明、一段“数据概况”；
   - 规矩：生年不详留空另给推算岁数；年轻名人开局就在；孩子作为家里的孩子；演义人物收不收看时代；开局所在是推定的要写“推定”；
   - 自检：交之前跑检查脚本（亲属引用、君主在世、年龄、立绘小节、84 郡齐全），0 错误才算交。
   - 几个开局共用一批人物时（比如同一个朝代的三个年份）：同一个人每份稿子用同一个 id（改过名也一样，名字按当年的叫法），不同的人绝不共用 id；交稿前做一次跨文件对照，把“同 id 不同名”“同名不同 id”都列出来人工判断。
   几份研究稿格式一样，后面的提示词生成、检查、做数据都能共用一套脚本。子代理有时写不了某个文件（比如“概况”被工具拦下），让它把正文附在回复里，由自己落盘。

10. **给玩家审的东西先画成图**：地盘表是 84 行文字，玩家很难看出问题；按郡归属画一张开局势力示意图（颜色取旗帜方案的底色），“韩只有两郡”“越占了四郡”一眼就看到。同样，开场动画先出静态样张（背景 + 立绘 + 诗），旗帜先出方案图，都在做进游戏之前给玩家看。

## 四、在游戏里怎么验证

- 开局后日志里每家一行汇总（君主、城数），和地盘表对得上。
- 选派系界面的地图、外交界面的附庸关系，和资料里的从属关系对得上。
- 人物面板里的年龄和资料一致；父子岁数说得通。

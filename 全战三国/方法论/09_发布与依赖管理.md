# 09 · 发布与依赖管理

## 384 里发生了什么

准备发布时，玩家问："它 depend on 任何 mod 吗？别人的 mod 也算在内。"

我们第一次回答"没有依赖"，这是错的。查下去实际有两处依赖，而且都不在我们自己的代码里：

1. **选派系界面**：一个派系能不能在选派系界面上被选到，取决于四张"界面"小表。
   - 这四张表：`faction_to_faction_groups_junctions`、`frontend_factions`、`frontend_faction_to_frontend_faction_leaders`、`frontend_faction_leaders`。
   - 我们借用的派系位在原版里这四张表都没有行；只有装了黑熊的"全派系解锁"包才有。
2. **开局存档**："所有派系都能选"这个开关写在开局存档里。当时生效的开局存档是别的 mod 带的：黑熊的，后来又被 NewFactionsAddon 的盖掉。我们自己的开局存档一直没生效（见第 10 节）。

另外还发现一处反方向的冲突：我们在意的文字、旗帜、开局存档，会被别的 mod 同名文件盖掉。

## 一、怎么查清一个时代 Mod 到底依赖什么

1. **列清单**：这个时代要用到的每一样东西——数据表的哪几行、哪些文字键、哪些图片和版式文件、开局存档、脚本调用的原版函数——在自己的包里有没有。
2. **对照来源**：没有的，查它来自游戏本体，还是来自某个创意工坊 mod。我们写了扫描脚本，把所有启用的包的文件目录和数据表行列出来，逐项对。
3. **模拟卸载**：让生成器在构建时假装"创意工坊目录不存在"跑一遍。
   - 该补的行必须自己补出来（例如借原版一个可选派系的界面行当模板，改键）；
   - 不该出现的派系不能被意外顶上界面；
   - 生成器不能报错。
4. **真的卸载**：在游戏里只勾自己的包开一局，确认能选、能开局、能过回合。这一步最有说服力，也最容易被跳过。
5. **反向检查"被谁盖掉"**：自己的每个关键文件（开局存档、等级名的文字、旗帜、界面版式），查有没有别的包带同路径的文件，谁的优先级高。

## 二、包的类型和优先级（实测）

| 情况 | 谁赢 |
|---|---|
| 同路径文件，一个在电影类型（movie）包，一个在普通 mod 包 | 电影包 |
| 同类型的包之间 | 文件名排序靠前的（`!` / `!!` 开头最靠前） |
| 数据库表片段（同一张表的多个片段文件） | 片段文件名靠前的那一行 |
| 文字文件（.loc） | 文件名靠前的；放在 `text/` 下、用 `!!` 开头 |

还有两条：

- 电影包**不勾选也会加载**。它适合放"必须压过别家"的少数文件，比如开局存档，但装上就一直生效。
- 普通 mod 包要在启动器里勾选才加载，适合放大部分内容。

## 三、我们最后的做法

- **设计上不依赖任何第三方 mod**：
  - 选派系界面的那几张表（链接、首领、界面人物、侧重风格、政党）：全部自己生成，只引用原版里有的键；键和黑熊的一样，同时开时我们的行整行顶掉他的；
  - 开局存档：自己生成，以游戏本体的为底。
  - 第一节第 3、4 步都做过了（2026-09-23：启动器里只勾 384 一个包，开局、布置、封官都正常）。
- **主包 + 一个小电影包**：
  - 主包（普通 mod 包）放全部内容，也包括一份开局存档；
  - 小电影包里只有开局存档，用来在装了别家开局存档 mod 的机器上压过去。
- **兼容性说明写清楚**：
  - 替换了哪个剧本（八王之乱）；
  - 190 等其他剧本不受影响；
  - 会和哪些同样改八王之乱开局存档的 mod 冲突。

## 真的卸载之后才发现的三件事

1. **界面行只是“有”还不够，还要“被允许选”**：可选的界面首领要属于这个派系的一个 playable 的政党（`political_parties` + 两张关联表）；黑熊给每家补的正是这个。
2. **别的 Mod 改过的界面版式**：列表里的小头像在原版版式里只画“盔甲”那一层、不画“脸”（脸那一层的图位被关掉了），而我们的立绘就是“脸”那一层。黑熊的版式打开了它，所以装着黑熊时一直是好的；只开我们自己时圆圈是空的。解决：自己带一份原版版式，只补上那几个图位。
3. **Steam 没开时**游戏验证不了 DLC，八王之乱的内容全部上锁、按钮变成「马上购买」——排查时容易误以为是 Mod 的问题，先看 Steam 在不在。

另外：同一个派系的界面首领，键要和常见的解锁 Mod 用同一个（派系键）。链接表的键是 剧本 + 派系 + 首领 三段，键不同就会多出一行，同时开时一家两个头像。

## 四、发布前检查单

1. 依赖清单（第一节）过一遍，结论写进说明。
2. 构建时跑完离线测试。
3. 在"只勾自己的包"的环境里开一局、过几回合。
4. 在"常见 mod 全开"的环境里再开一局，看有没有被盖掉的东西（年份、等级名、旗帜、头像）。
5. 190 剧本开一局，确认没被牵连。
6. 包的大小：立绘多的话包会很大（384 主包约 860 MB，绝大部分是立绘和开场动画）；上传前确认平台的大小限制（未验证）。
7. 发布渠道：创意工坊（游戏启动器自带上传）。具体流程见下一节，第一次发布时按实际界面核对后补全。
8. **依赖扫描**（`TW3K/tools/check_self_contained.py <mod 源码目录>`）：
   - 数据表里每一个“指向别的表”的值，都去原版和包自己那里找；只在创意工坊 mod 里有的，就是依赖。
   - 2026-09-24 的 384：87665 处引用，**0 处**只在别的 mod 里。
   - 2026-09-25 发布前复查：87667 处引用，还是 0 处；只勾 384 一个包（两个“不勾也会加载”的电影包挪走）实开一局晋，169 人、0 失败，过到第 2 回合。
   - 另有 823 处哪里都找不到，是引擎内部的枚举和编译好的数据（比如性格特性），属于正常。
9. **隐私**：公开的包和页面里不能有私人内容（只给自己用的角色、个人信息）。上传前在包和说明里搜一遍关键词。
   - **扫打出来的包本身**，不是只看源文件：把包解开，每条文字（.loc）、每张数据表的每个格子、每个脚本、每个文件名都搜一遍。
   - 2026-09-25 发布前就这样扫出一处：私用角色的兵器、坐骑改名（说明里写着那个角色的名字）放在了公开包里，按剧本生效，所有玩家都会看到。改法是挪到私用的包里，用它自己的 campaign group。
   - 数字会误报（名字编号里恰好有那串数字），史料原文也会碰上同一个词，逐条看一眼再下结论。

## 五、上传到创意工坊（待第一次发布时核对）

1. **只传主包**：
   - 游戏启动器里只勾主包，开一局、过几回合（第四节第 3 条），Steam 要开着。
   - 那个只装开局存档的小电影包是给装了 NewFactionsAddon 的人用的，不要一起传。电影包不勾也会加载，会影响所有订阅者。
2. **预览图**：
   - 做一张方形的 PNG，一般 512×512，1 MB 以内；
   - 放在 `data/` 里、和包同名（例如 `!rtz_era_384.png`）。
3. **启动器 → 模组管理 → 创建 / 上传**：
   - 选这个包，填标题、说明、标签；
   - 可见性先设成“私有”或“仅好友”。
   - 第一次上传要在 Steam 里同意创意工坊协议。
4. **自己先订阅试一遍**：把 `data/` 里的本地包挪走，只用订阅下来的那份开一局，确认和本地版一样。
5. **说明里写清楚**：
   - 需要「八王之乱」DLC；
   - 替换八王之乱剧本，190 等其他剧本不受影响；
   - 只能新开一局；
   - 不依赖任何别的 mod；
   - 和哪些同样改八王之乱开局的 mod 冲突。
6. **以后更新**：
   - 同一个包重新上传，写更新说明；
   - 数据改了开局布置的，提醒“需要新开一局”；
   - 只改文字和图的，旧存档也能用。
